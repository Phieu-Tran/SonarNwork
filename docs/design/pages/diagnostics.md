# Diagnostics page

The diagnostic page is a two-part workbench: a check rail for choosing the
question and a stage for configuring, running, and reading the answer.

- Keep the active check and direction visible in the rail.
- Order the stage as configuration, safety/context messages, run controls,
  live output, then verdict and facts.
- Do not present remote-only visibility as a local result. Explain the required
  vantage or token in the empty state.
- Below 840 px replace the card rail with a labeled select; do not stack every
  check card above the primary action.
- A result must communicate status with text plus color. Unknown or incomplete
  execution must never appear as success.
