# Operations page

Operations groups higher-risk, long-running, or system-level actions. It uses a
two-column grid on wide windows and stacks below 980 px.

- Capture and monitor actions run directly once their required input is valid;
  keep bounds, runtime state, and technical validation visible near the action.
  Operations use risk labels (Safe, Medium, High, Critical) to categorize scanner
  profiles, ensuring that potentially sensitive operations are explicitly managed.
- Inventory, monitor, capture, and timeline areas expose loading, empty, error,
  and populated states instead of showing blank containers.
- Use one clear run/refresh action per card and disable it while work is active.
- Show command text and runtime output in the mono font. Never hide exit state
  or silently reinterpret an unavailable desktop capability as success.
